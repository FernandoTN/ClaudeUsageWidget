## Verified sound

Areas checked in this audit and found correct. Several of these were *hypotheses I formed and then disproved* — recorded so the next auditor does not re-open them.

- **No force-unwrap or trap surface from untrusted data.** `rg` over `Claude Usage/**`: zero `try!`, zero `as!`, zero `fatalError`/`preconditionFailure`/`assertionFailure`. The single `URL(string:)!` (`ClaudeStatusService.swift:21`) is a compile-time-constant literal. `Dictionary(uniqueKeysWithValues:)` in `saveMeasuredSessionHistory` cannot trap — its keys come from a `[UUID: …]` dictionary, so uniqueness is structural.
- **No `DispatchQueue.main.sync` anywhere** in the app (only `stateQueue.sync` on a private serial queue, `ErrorRecovery.swift:157`). No deadlock of that shape exists.
- **No retain cycles found.** Every long-lived closure across the audited files uses `[weak self]`. `NSControl.target` is weak, so status-item action targets do not cycle; `multiProfileTarget` is explicitly `weak` (`StatusBarUIManager.swift:24`).
- **`MenuBarManager.setup()` is idempotent.** `:147-150` calls `cleanup()` on re-entry; `cleanup()` (`:330-382`) invalidates `refreshTimer`, removes all nine stored observer tokens, clears `cancellables`, and stops the shortcut handler. AppDelegate's 3-second headless retry (`:113-121`) therefore does **not** duplicate timers or observers. I initially suspected a duplicate-timer bug here and disproved it; the residual is L1 only.
- **Lab mode cannot produce two concurrent status-item owners.** `AppDelegate.swift:63-69` returns before `MenuBarManager()` is ever constructed, and `LabController.shared` — holder of the only other `StatusBarUIManager()` (`LabController.swift:17`) — is referenced from exactly that one site. Lab tiles appear *instead of*, never *alongside*, the real ones. The gate is a bare env var (`LabMode.swift:18`) with no `#if DEBUG`, so accidental entry is possible, but **the owner's "two apps in parallel" symptom is not lab mode.** The nearest real candidate is M10.
- **The auto-import cannot mint duplicate profiles under a degraded `cfprefsd`.** I traced this specifically as a suspected roster-destroying path and it is blocked: `reloadAfterCredentialSync` guards `guard !reloaded.isEmpty else { return }` at `ProfileManager.swift:949`, **before** the three one-time imports at `:962-964`. An unreadable `profiles_v3` returns early rather than passing the content guard with an empty roster.
- **No UserDefaults key is written from two places with different encodings.** Mechanical census of every `forKey:` literal and every `static let` key constant across `ProfileStore`, `SharedDataStore`, `Constants`, and the four services: all key strings are distinct and each has exactly one writer. (`sentNotifications` appears twice — both are the getter/setter of one property in `NotificationManager.swift:16,19`.)
- **Ring buffers are capped.** `switchHistory_v1` at 30 (`SharedDataStore.swift:239-252`), `measuredSessionHistory_v1` at 4 samples/profile (`MenuBarManager.swift:2215,2221-2223`). Only the key sets are unpruned (L3).
- **`loadAutoSwitchThreshold` / `loadAutoSwitchWeeklyThreshold` handle the missing key correctly** (`SharedDataStore.swift:156-174`) — `stored > 0` guards the `double(forKey:)` zero and falls back to 95/99, then clamps to 80…100. This is the pattern H8 should adopt.
- **The auto-switch queue semantics are correct.** `selectQueuedSwitchTarget` (`MenuBarManager.swift:3019-3040`) drops only deleted profiles; an entry ineligible right now is skipped but stays queued. Consumption happens only after a successful activation (`:3074-3080`). The `cameFromQueue` attribution at `:2704` is correct when the queue yields nothing.
- **Switching into a dead or unhydrated account is gated.** `checkAutoSwitchIfNeeded` refuses while `credentialHydrationState == .loading` (`:2638`), and `activateProfile`'s dead-login gate never applies credentials still expired after the pre-apply refresh. Candidate headroom checks see server-affirmed stamps; `autoSwitchTriggerUsage` strips *inferred* stamps from the switch-away trigger.
